## A1 一键演示环境 + 切到真实 LLM 模式

**一条命令起全部**（已有，不用新脚本）：

| 命令 | 效果 |
|---|---|
| `python scripts/dev.py` | 起后端 + 前端，不开窗口 |
| `python scripts/dev.py --app` | 同上 + 弹出**无地址栏独立窗口**（拍摄用这个） |
| `python scripts/dev.py --open` | 同上 + 默认浏览器打开 |
| `python scripts/dev.py --backend` | 只起后端（A6 落日志用这个） |

脚本自带三件防翻车的事：清掉 8000/5173 上的残留进程、把本机 `node` 补进 PATH、**清掉代理环境变量**（否则页面请求 8000 会被送去绕代理，表现为"后端活着但页面连不上"）。

**三档模型模式**（改 `.env`，改完**必须重启后端** —— `load_dotenv` 只在导入时执行一次）：

| 档位 | `.env` 设置 | 卡片角标 | 什么时候用 |
|---|---|---|---|
| 真实模型 | `DEEPSEEK_API_KEY=sk-xxxx`、`DEMO_MODE=false` | 「模型建议」（紫） | **第 3 章必须拍到这个** |
| 规则降级 | 把 `DEEPSEEK_API_KEY` 那行注释掉 | 「规则兜底」（橙） | 第 5 章故障演示 |
| 离线回放 | `DEMO_MODE=true` | 「缓存命中」（灰） | 断网兜底，正常不用 |

> 不想改 `.env` 也能临时切档（重启生效，适合一条镜头内来回切）：
> `DEEPSEEK_API_KEY= python scripts/dev.py --app` —— 前置的空变量会让本次进程读不到 Key，直奔降级。

**怎么验**：最省事是点页面上的「问决策器」，看卡片右上角角标（见 §0 第 4 步那张表）。
想在终端里看原始数据，可以：

```bash
curl -s -X POST 127.0.0.1:8000/api/decisions -H "Content-Type: application/json" -d '{"trigger":"manual"}' | python -c "import json,sys; d=json.load(sys.stdin); print('source =', d.get('source'))"
```

`source` 的值就是角标依据：`llm`=模型建议（紫）、`fallback`=规则兜底（橙）、`cache`=缓存命中（灰）。

## A2 演示数据种子 + 一键重置

```bash
cd C:\Users\Y7000P\WorkBuddy\2026-10-28-16-31-40
python scripts/seed_video.py            # 清空 → 灌 5 条冲突日程 → 打印预期画面
python scripts/seed_video.py --dry-run  # 只看不写
```

**为什么另做一个脚本，不用 `scripts/seed.py`**：`seed.py` 是 10 条的"功能演示"数据，列表会滚屏；
`seed_video.py` 只留 5 条、一屏装得下，且保证正好 **1 处硬冲突（重叠 60 分钟）+ 1 处软冲突（间隔 5 分钟）**，
让宠物稳定停在 `alert`。

**时刻是相对锚定的，且会自动避开凌晨**：脚本判断"今天剩不下这 6.5 小时"时，整批滚到**次日 09:00**。
所以晚上开拍不会生成「团队周会 00:23」这种出戏钟点。实跑回显：

```
  10-31 09:00 → 11:00  写项目架构文档   [与 ② 重叠 60 分钟]
  10-31 10:00 → 12:00  评审 PR #42      [与 ① 重叠 60 分钟]
  10-31 13:00 → 14:00  团队周会         [与 ④ 只隔 5 分钟]
  10-31 14:05 → 15:00  整理实验数据     [与 ③ 只隔 5 分钟]
  10-28 16:00 → 18:00  整理季度复盘材料 [逾期 2 天]

预期画面：宠物 alert · 硬冲突 1 · 软冲突 1 · 拖延指数 > 0
```

**重置**：再跑一次即可。它会连同**干预历史一起清掉** —— 否则节奏闸门的"今日还剩 N 次"
会带着上一遍的残留，观众不知道那几次是哪儿来的。十几遍重拍都不怕。

## A4 「连续忽略 3 次 → 该类不再推送」的复现路径

**最短操作序列（纯界面，4 步）**：

| 步 | 操作 | 画面 |
|---|---|---|
| 1 | 点顶栏 **「问决策器」** | 出现干预卡片 |
| 2 | 点卡片上 **「不再提醒这类」** | 卡片底部提示 `这类建议已被忽略 1/3 次` |
| 3 | 重复 1+2 两次 | 计数走到 `2/3`、`3/3` |
| 4 | 第 3 次点完 | 提示变 `已记住：这类建议不再出现` |

> 「问决策器」走的是 `manual` 触发，**绕过触发判定与冷却**，所以三步可以连着点，不用等 45 分钟。

**Bonus 镜头（强烈建议拍）**：第 4 次点「问决策器」，等约 9 秒后页面顶部出现

```
本轮决策：不打扰
刚连续三次的提醒都被撂下了，现在又是晚上九点二十，你能量很低，这会儿不再打扰更合适
```

第二行是**模型的原话**（`payload.summary`），由前端新增的提示条转述。
它比任何解释都有说服力：模型读到了 prompt 里的负面清单，主动放弃了重排建议。

> **⚠️ 实测更正（2026-10-30 21:2x）**
> 手册早前的版本写的是「第 4 次点击会弹出 `类型 reschedule 已被用户降权，本次不予送达`」。
> **这句话在正常路径下拍不出来。** 那句文案是 `decision_flow.py` 里的**保险丝**：
> 被降权的类型已经写进 prompt 的负面清单，模型自己就不会再提 `reschedule`
> （实测连续 3 次都返回 `decision_type = no_action`），所以兜底拒发根本不会触发。
> 它只在"模型没听话"时才会出现 —— 那是异常情况，不该当卖点拍。
>
> 另外：在加提示条之前，`no_action` 是**完全静默**的 ——
> `InterventionCard.tsx` 对 `no_action` 直接 `return null`，而 `hint` 只在
> `delivered === false` 时才设置，`no_action` 是"送达了"，所以提示条也不出。
> 表现为「点一下、等 9 秒、画面纹丝不动」。这是设计如此，不是 bug。

**镜头要的那条日志（后端终端，2 秒特写）**：

```
18:26:19 INFO    app.api.interventions | 干预反馈: id=ivt_1737534a24a5 kind=mute -> muted=['reschedule'] ignore={'reschedule': 3}
```

第三次点击才会出现 `muted=['reschedule']`；前两次是 `muted=[]`、`ignore={'reschedule': 1}` / `2`。
想先确认进度：`curl -s 127.0.0.1:8000/api/interventions/profile`。

**证明"模型真的看见了"**（第 6 章的硬证据）：

```bash
python scripts/show_prompt.py
```

实跑回显（降权发生后）：

```
## 用户反馈（真实发生过，务必尊重）
>> - **已被用户彻底降权的干预类型**：reschedule
     本轮**绝不许**输出这些 decision_type。若通盘考虑后你认为唯一合理的动作正是
     被降权的类型，就返回 decision_type = "no_action" —— 沉默比重复一次已被拒绝的建议更有用。
```

未降权时这一行是 `- 目前没有被降权的干预类型。`，脚本会提示你先去点满 3 次。
（脚本走的是生产同一条链路 `load_inputs → compute_state → load_traces → build_request → render_user_prompt`，
打印出来与真实请求里的文本**逐字一致**；只读，不调模型、不写库。）

## A5 第 5 章「制造故障」操作卡

### 幕 1 · 断网 → 卡片仍在，角标变「规则兜底」，宠物不变

**最快（约 2 秒，推荐）**：桌面双击 `断AI演示.bat`
（它自动做两件事：先跑 `seed_video.py` 重置数据，再用假 base url 起服务并开浏览器）

**等价的手敲版**：

```bash
cd /d C:\Users\Y7000P\WorkBuddy\2026-10-28-16-31-40
python scripts/seed_video.py
set DEEPSEEK_BASE_URL=http://127.0.0.1:9/v1
python scripts/dev.py --open
```

> **⚠️ 实测更正（2026-10-30 22:2x）：手册早前写的 `set DEEPSEEK_API_KEY=` 在 cmd 里是错的。**
> `set VAR=` 在 cmd 中是**删除**变量，而 `config.py` 里的 `load_dotenv` 随后会把 `.env`
> 里的真 Key 补回来 —— 结果模型照样能用，角标还是紫色，根本断不掉。
> 要断就断 `DEEPSEEK_BASE_URL`（指到一个死端口），它优先级高于 `.env`，实测 2.25 秒降级。

> **⚠️ 第二个坑（更要命）：断 AI 之前必须先清掉降权。**
> 规则兜底引擎产出的是 `decision_type = reschedule`。如果此时 reschedule 已被点满 3 次降权，
> 兜底卡片会被**降权闸门**拦下（`delivered=false, blocked_by=muted`），
> 你看到的是顶部一行「类型 reschedule 已被用户降权，本次不予送达」，**橙色卡片根本不出现**。
> 所以拍这一章前务必先 `seed_video.py` 重置（`断AI演示.bat` 已经帮你做了）。
>
> 反过来：这也正是那句"降权拒发"**唯一能稳定拍到**的场景 —— 断 AI + 已降权，
> 规则引擎照提 reschedule，闸门拦下，顶部就出那句话。

**真断网（更有说服力，但要等超时）**：拔网线 / 开飞行模式 → 模型调用在 `LLM_TIMEOUT_SEC`（默认 15 秒）后超时 → L0 降级。
嫌 15 秒太长就在 `.env` 里临时写 `LLM_TIMEOUT_SEC=3`，拍完改回来。

**第三档（最可控）**：`.env` 里把 `DEEPSEEK_BASE_URL=http://127.0.0.1:9/v1`（一个必然连不上的地址），重启后端。

**预期画面（三档都一样）**：

| 元素 | 故障前 | 故障后 |
|---|---|---|
| 干预卡片 | 出现 | **仍然出现**（规则降级引擎接管） |
| 右上角角标 | 「模型建议」（紫） | 「规则兜底」（橙） |
| caveats | 无 | 明说"本条由规则生成" |
| 宠物表情 | alert | **alert —— 一字不变** |
| `/api/state` 的 `pet.mood` | `alert` | `alert` |

**口播点**：宠物的脸是确定性代码算的，从来没经过模型；模型只负责台词那一句。
所以模型挂掉，仪表盘照常准。

### 幕 2 · 喂一个不存在的日程 ID → 规则 5 拦截

```bash
python scripts/demo_bad_id.py
```

实跑回显：

## A6 日志可读性（大字号 + 慢滚动）

后端日志只有 stdout 一路，所以先落文件再慢放。**开两个终端**：

```bash
# 终端 A（不拍）
python scripts/dev.py --backend > backend.log 2>&1

# 终端 B（上镜头）
python scripts/watch_log.py backend.log --slow 0.8
```

| 参数 | 作用 |
|---|---|
| `--slow 0.8` | 每行间隔 0.8 秒（念稿跟不上就调到 1.5~2.0） |
| `--tail 6 --once` | **开拍前预演一遍**：只放最后 6 行就退出，不进入跟踪 |
| `--all` | 不过滤，全量（默认只放决策链路的行） |
| `--no-color` | 关闭高亮（cmd 老控制台不支持 ANSI 时用） |

默认只放含「决策 / 闸门 / 干预 / 反馈 / LLM / 校验 / 降级 / 降权 / 节奏」的行，
SSE 心跳与 SQLAlchemy 全部滤掉 —— 镜头里滚动的应该句句有效。

**字号**：脚本管不了字号，靠终端 —— Windows Terminal 用 `Ctrl` + 滚轮放大到 18~20pt；
老 cmd 在标题栏右键「属性 → 字体」改。建议录之前先用 `--once` 对一遍行宽，别出横向滚动条。
